This release states each fact once — a module's checks, a tool's pin, a toolchain version, a limit, a
default — and derives or checks every other place that names it ([ADR-0013](https://github.com/hynix666/ULTRA-TEMPLATE/blob/v1.2.0/docs/adr/0013-declare-each-fact-once.md)).

### Checks that can now turn your build red

- **Hygiene rule 16:** a tool version written into a workflow or action. Move it into `scripts/tools/tools.json`, and install or run the tool through `scripts/tools.mjs`.
- **Hygiene rule 17:** a copy of a toolchain version that differs from its declaration: `engines`, the `@types/node` major, a Dockerfile `node:`, `golang:` or `python:` tag, a Dev Container feature, mypy's `python_version` against the `requires-python` floor, the uv pin against `required-version`, or two Node modules on different Biome versions.
- **The contract:**
  - each task service is now also started once for each configuration value `scripts/contract/tasks-api.json` lists, and must take the good ones and refuse the rest;
  - its listening line must report `port` and `shutdownTimeoutMs`;
  - a refused configuration writes one `invalid configuration` JSON line to stdout and exits 2;
  - each limit is tested at its bound;
  - a service you changed on your own will meet these first.
- **The image probe in CI:** started with no configuration, a task service's image must answer on the contract's default port, report every default, and exit 0 on SIGTERM. Its Dockerfile must `EXPOSE` the default port and set no contract variable.
- **Boundary checks:** a file below a service's composition root that reads the clock, randomness or the environment now fails its module's check.
- **`check-facts`,** which replaces `check-rules`: a module's `facts` script (was `rules`) prints what it repeats, and the web app and MCP server now also print the API's default port.
- **`check-architecture`:** every module needs exactly one element in the architecture model, linking its README.
- **check-docs rules 9 and 10:** a `.claude/settings.json` hook that runs an untracked script, and a generated block that no longer says what its source says (`node scripts/generate-docs.mjs` rewrites it).
- **verify:** a pinned tool on PATH at another version than its pin now fails, and in CI a check it would skip for want of a tool or cgo fails. actionlint run without shellcheck on PATH is reported as a skip of its shell-script rules, where it used to read as a full pass.
- **shellcheck is pinned** beside actionlint, and CI lints the workflows with that one rather than the runner's own: a `run:` script the runner's shellcheck passed can fail on the pinned version's rules, and a shellcheck on PATH at another version fails verify.

### Where an update is likely to conflict

The three-way merge keeps your changes and leaves a conflict where both sides changed the same lines. Expect one in:

- **`scripts/modules.mjs`:** its module list is gone. Keep your intent in the module's new `module.json`.
- **`.github/workflows/verify.yml`:** each module job is now a checkout and `.github/actions/module`. Move a step you added into that module's `module.json` checks.
- **A module's `biome.jsonc`:** now `{ "root": false, "extends": "//" }` over the root `biome.jsonc`. Keep a rule you switched off for one module after the `extends`.
- **The services' startup code (`main.go`, `app.go`, `main.ts`, `main.py`):** the listening and refusal lines changed.
- **The READMEs and `docs/toolchain-updates.md`:** the values they restate are now generated blocks.
